# 组织与用户权限 POC

单文件离线 HTML 原型。侧栏和用户列表对齐生产管理后台，并按最新 PRD 用左侧只读组织树筛选用户。

## 打开方式

### 本地静态服务

```bash
python3 -m http.server 4173
```

在本目录执行后访问 <http://localhost:4173/>。

### GitHub Pages

线上地址是 <https://babysharpyin.github.io/org-admin-poc/>。Pages 从 `gh-pages` 分支发布，合并本仓库的功能分支不会自动更新该站点。需要预览线上效果时，把当前 `index.html` 发布到 `gh-pages`。不要为了预览直接合并。

## POC 范围

### 组织与用户

- 侧栏入口是「组织与用户」，页面标题是「用户列表」。
- 左侧组织树是客户系统的只读投影，不提供组织新增、编辑或删除。用「刷新组织」重新拉取这份投影。
- 选中节点后，右侧只显示该节点及其全部下级中的用户。再次点击该节点，或点「全部用户 / 清除选择」，筛选为空，展示全部用户。
- 没有员工工号的用户没有组织归属，只出现在未筛选的全部用户里。
- 用户列表列：姓名、账号、邮箱、手机号、角色、操作（查看）。列表不展示所属组织。
- 保留「新增用户」。详情可编辑：姓名、账号、邮箱、手机号、功能角色、员工工号。
- 「用户信息」是客户系统同步回来的原始 JSON 字符串，只读，不拆成组织或岗位表单。
- 是否同步只看员工工号。有工号就请求一次客户用户信息；没有工号则不同步、无组织归属，只保留直接授权。同步要么完成，要么不发起。
- 有工号但客户系统没有匹配用户时，只保存工号，不写入用户信息，也不自动授权。
- 修改员工工号会先弹出第二次确认，确认后按新工号重新同步一次。新建或修改工号都会触发这一次同步。
- 用户列表仍可进入批量赋予 / 回收功能角色。回收前校验至少保留一个角色，系统只报错，不自动补角色。批量操作只作用于当前勾选用户。

### 知识库权限示例

从侧栏「数据资产 / 知识库权限」进入。

- 有效权限 = 组织（含上级）授权 ∪ 用户直接授权。
- 直接授权跟随人员。员工工号变更导致组织归属变化后，直接授权仍在。
- 保留「单个添加」和「按组织筛选添加」。按组织筛选只是筛人，确认后仍按用户写入直接授权。
- 组织授权单独维护，作用于所选节点及全部下级。
- 已有成员不会重复添加，创建者固定为所有者。
